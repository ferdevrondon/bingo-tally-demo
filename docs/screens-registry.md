**Status vocabulary used here:** `Done` (works end-to-end for its purpose) · `Partial` (real UI + real interactions, but key data/flow missing, **or** code complete but its phase acceptance test is not yet recorded) · `Stub` (renders, but content is hardcoded/template and buttons do nothing) · `Broken` (type-errors, or misused props / dead on arrival) · `Missing-but-linked` (nav points at a route that does not exist) · `Not started` (used only in the Planned section: specified in `BACKEND_PLAN.md`, no code yet).

**Persistence note:** Supabase is now the source of truth for **auth**, the **single admin session** (Phase 2) and, since Phase 3, the **catalog**: `players` and `round_templates`. `/players` and `/rounds` are Server Components that read through `lib/data/players.ts` (`listPlayers`) and `lib/data/rounds.ts` (`listRoundTemplates`), both `react` `cache()`d, filtered to the current house and `active = true`, with RLS doing the real scoping. Writes are Server Actions in `lib/data/player-actions.ts` / `lib/data/round-actions.ts` (create, update, soft delete `active = false`), which re-validate with zod, take `house_id` from the server, call `refresh()`, and route failures through `lib/data/reject-write.ts` (observer → "Solo lectura" error; replaced admin session → sign-out + `/login?reason=replaced`). The client shows errors via `lib/write-feedback.ts` (sonner toast). Both mock `data.json` files are deleted. **Still not persisted:** the live jornada. `lib/round-draft/` remains React context + `localStorage` (key `bingo:round-draft:v1`, `storage.ts` still present until Phase 4). Its provider moved out of the root layout into `app/(app)/(game)/layout.tsx`, which seeds it with the DB catalog. S-03, S-07, S-10, S-11, S-17 still use hardcoded arrays/literals.

**Route layout:** `app/(auth)/` holds `/login` and `/session-conflict` (bare layout). `app/(app)/` holds every signed-in screen; its layout fetches the user and the current house (`getCurrentHouse()`, which carries the member's `role`), mounts `HouseProvider` (source of `useRole()`), mounts `AdminSessionGuard` for admins only, and renders `AppSidebar` + `SiteHeader`. **New in Phase 3:** `app/(app)/(game)/` is a route group (URLs unchanged) holding `/new-game` and `/active-round`; its `layout.tsx` is an async Server Component that loads `listPlayers()` + `listRoundTemplates()` and mounts `RoundDraftProvider` with them. `app/layout.tsx` now holds only `ThemeProvider` + `Toaster`. All `useRoundDraft()` consumers live under `(game)`. `app/(app)/__themecheck__/` is an empty design-tool folder and is excluded from this registry.

## Flow Map

**Guest → Admin sign-in (Phase 2, single admin session)**
`[S-01 Login]` → (password) → `resolveAdminSessionAfterLogin()` · (Google) → `[S-02 /auth/callback]` → `resolveAdminSessionAfterLogin()`, then:
- no conflict (`none` / `mine` / `other_stale`) → claim if needed → `/` [S-03]
- `other_active` → `[S-19 /session-conflict]` → "Mantener sesión aquí" → `/` [S-03] (other sessions signed out) **or** "Seguir en el otro dispositivo" → `[S-01]` (this device signed out)
- On the other device (device A): `AdminSessionGuard` sees the takeover (Realtime or 60 s heartbeat) → `[M-13 /login?reason=replaced]` = S-01 with an info Alert. *Verified in the Phase 2 two-device test.*
- A catalog write (S-05, S-06, S-08, S-09) from a session that lost the claim → `rejectWrite()` → `[M-13]`. *New in Phase 3.*
- Already signed in: `(app)/layout.tsx` sends an admin who lost the claim to an active device to `[S-19]` on any signed-in route.
- OAuth failure → `[S-01 /login?error=…]`, which shows a destructive Alert.

**Guest → Observer (new in Phase 3)**
