**Persistence note:** Supabase is the source of truth for **auth**, the **single admin session** (Phase 2), the **catalog** (`players`, `round_templates`, Phase 3) and, since Phase 4b, the **live game session**.
- **Catalog.** `/players` and `/rounds` read through `lib/data/players.ts` / `lib/data/rounds.ts` and write through Server Actions, the same as before.
- **Reads for the live game.** `lib/round-draft/fetch-state.ts` (`fetchGameSessionState`) reads the house's `status = 'active'` game session: catalog players, `game_session_players`, `tickets`, `ticket_numbers`, `game_session_rounds` and the last `activity_log` rows. It builds a `RoundDraftState` from them. The same function runs on the server (`lib/data/load-game-session.ts`, `cache()`d, used by the `(game)` layout) and in the browser (the provider's background re-sync).
- **Writes for the live game.** They go **straight from the browser** to the 4a SQL functions via `supabase.rpc` (`lib/round-draft/game-api.ts`), each with a fresh `request_id`. `lib/round-draft/context.tsx` applies frequent actions optimistically, runs the calls through an ordered promise queue, then re-reads the game session about 100 ms after the queue goes idle (300 ms before Phase 5). The browser re-sync passes the known game session id, so its rows are read together with the active game session in one round trip.
  - **Phase 5:** it also re-reads on every Realtime `activity_log` row of the house, and on a channel reconnect. The same yields apply: none while this tab has actions in flight, and none once this tab is ending or discarding the game session. For observers, `perform` returns `read_only` without dispatching or calling SQL.
  - Structural actions await that read, and they are not optimistic: add ticket, pick round, close round.
  - End and discard skip the re-read.
  - Errors show a Spanish sonner toast (`GAME_ACTION_ERROR_MESSAGES` in `lib/data/game-action-result.ts`), and the re-sync reverts the optimistic change.
  - The only Server Action is "Iniciar jornada" (`lib/data/game-session-actions.ts` → `startGameSession`), because it redirects.
- **Ticket auto-assign and row compaction (feat/assign-ticket-by-priority):** `lib/round-draft/assign-ticket.ts` holds `assignTicket`, `compactLine` and `movedPlays`, which mirror `private.first_free_ticket` and `private.compact_line` (the database decides; the browser only predicts for the optimistic UI). `purchaseNumber(gameSessionId, number, playerId, requestId)` no longer sends a ticket and gets the chosen ticket back. Every action that frees plays goes through `performFreeing` in `context.tsx` (release by tap, `remove_player`, `edit_player_numbers`, `resolve_carryover`) and toasts once it is saved. Errors `no_free_ticket` and `invalid_number` have Spanish messages. Not compacted once the open round has a winning number; old holes close the first time their number is compacted (no data migration). Money never moves; each move is a `number_moved` activity row.

- **Game rules v2 (4c):**
  - **Balance.** A player has one signed `balance` per game session (`game_session_players.balance`), not the positive/negative pair. `lib/round-draft/balance.ts` shows it as "Debe $X" / "A favor $X" / "Al día", or as `±$X`.
  - **Prizes.** A round template has no kind: it has 1–5 prizes. The round copies them when it starts. Each winning ticket is paid `prizes[slot]`; a gifted ticket is paid prize − P (`prize-rules.ts` `ticketPrize`).
  - **Check-in** moves no money.
  - **House result.** `game_sessions.house_balance` is the house result: sales − prizes + the round margin (gifts that lost, unsold numbers that lost, unsold numbers that won). Recharges are cash and do not count.
  - **Summaries.** Closing a round reads `fetchRoundSummary()`. Ending the game session reads `fetchSummary()`. Both come from `game-api.ts` and are shown with `components/house-result-breakdown.tsx`.
