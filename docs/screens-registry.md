**Status vocabulary used here:** `Done` (works end-to-end for its purpose) · `Partial` (real UI + real interactions, but key data/flow missing, **or** code complete but its phase acceptance test is not yet recorded) · `Stub` (renders, but content is hardcoded/template and buttons do nothing) · `Broken` (type-errors, or misused props / dead on arrival) · `Missing-but-linked` (nav points at a route that does not exist) · `Not started` (used only in the Planned section: specified in `BACKEND_PLAN.md`, no code yet).

**Persistence note:** Supabase is the source of truth for **auth**, the **single admin session** (Phase 2), the **catalog** (`players`, `round_templates`, Phase 3) and, since Phase 4b, the **live game session**.
- **Catalog.** `/players` and `/rounds` read through `lib/data/players.ts` / `lib/data/rounds.ts` and write through Server Actions, the same as before.
- **Reads for the live game.** `lib/round-draft/fetch-state.ts` (`fetchGameSessionState`) reads the house's `status = 'active'` game session: catalog players, `game_session_players`, `tickets`, `ticket_numbers`, `game_session_rounds` and the last `activity_log` rows. It builds a `RoundDraftState` from them. The same function runs on the server (`lib/data/load-game-session.ts`, `cache()`d, used by the `(game)` layout) and in the browser (the provider's background re-sync).
- **Writes for the live game.** They go **straight from the browser** to the 4a SQL functions via `supabase.rpc` (`lib/round-draft/game-api.ts`), each with a fresh `request_id`. `lib/round-draft/context.tsx` applies frequent actions optimistically, runs the calls through an ordered promise queue, then re-reads the game session about 300 ms after the queue goes idle.
  - Structural actions await that read, and they are not optimistic: add ticket, pick round, close round.
  - End and discard skip the re-read.
  - Errors show a Spanish sonner toast (`GAME_ACTION_ERROR_MESSAGES` in `lib/data/game-action-result.ts`), and the re-sync reverts the optimistic change.
  - The only Server Action is "Iniciar jornada" (`lib/data/game-session-actions.ts` → `startGameSession`), because it redirects.
- **Gone:** `storage.ts` (localStorage), `lib/round-draft/players.ts` (`SYNC_CATALOG`), `LOG_ACTIVITY`, the seed activity, `NUMBER_PRICE` and `hasDraftProgress`. The reducer charges, refunds and pays at the open round's `linePrice`.
- **Still mock:**
  - S-03's stats and jornada number.
  - S-06's heading ("Jornada #42 / Monday, Sept 7") and embedded `RoundHistoryCard`.
  - M-06.
  - S-07, S-10, S-17, which are the history side and belong to Phase 6.
  - S-11 (no-op forms).

**Route layout:** `app/(auth)/` holds `/login` and `/session-conflict` (bare layout). `app/(app)/` holds every signed-in screen. Its layout fetches the user and the current house (`getCurrentHouse()`, which carries the member's `role`), mounts `HouseProvider` (the source of `useRole()` / `useHouse()`), mounts `AdminSessionGuard` for admins only, and renders `AppSidebar` + `SiteHeader`.

`app/(app)/(game)/` is a URL-less route group holding `/new-game` and `/active-round`. **Changed in 4b:** its async `layout.tsx` now loads `loadActiveGameSession()` + `listRoundTemplates()`; it no longer calls `listPlayers()`, because catalog players come inside `fetchGameSessionState`.
- With **no** active game session, it renders **M-18** ("No hay una jornada activa" + "Iniciar jornada") instead of the page.
- Otherwise it mounts `RoundDraftProvider` with `initialState` and `roundTemplates`. The provider picks the game API's error handling from `useHouse().role`.

`app/(app)/(game)/new-game/layout.tsx` adds the breadcrumb (M-09). `app/layout.tsx` holds only `ThemeProvider` + `Toaster`. `app/(app)/__themecheck__/` is an empty design-tool folder and is excluded from this registry.

**Error states (not screens):** the Supabase loaders throw on a failed read, and two `error.tsx` boundaries render the shared `components/load-error.tsx` fallback: a destructive Alert "No se pudieron cargar los datos" / "Revisa tu conexión e inténtalo de nuevo." with "Reintentar" (`unstable_retry`).
- **`app/(app)/error.tsx`** renders **inside** the `(app)` layout, so the sidebar and header stay. It catches:
  - S-08 (`listPlayers`) and S-09 (`listRoundTemplates`).
  - The nested `(game)` layout: **now** `loadActiveGameSession()` (any of the six reads in `fetchGameSessionState`, or `getCurrentHouse`) and `listRoundTemplates()`, for S-05, S-06 and M-18.
  - "Reintentar" re-runs those loaders.
- **`app/error.tsx`** is the last resort for throws from `app/(app)/layout.tsx` itself and from `(auth)` pages (S-19). It renders full screen, without the sidebar.
- **Deliberately absent:** `app/(app)/(game)/error.tsx`. An `error.tsx` does not wrap the layout of its own segment.
- **Not covered:**
  - `app/layout.tsx`, S-02 `/auth/callback` and `proxy.ts`.
  - Failed **writes**. Catalog Server Actions keep reporting through `lib/write-feedback.ts`. Game actions report through the provider's toast.
  - **New (flag):** a failed **background re-sync** in the browser is only `console.error`'d. If an action fails *and* the re-read that should revert it also fails, the optimistic change stays on screen with no indicator until the next navigation or successful action.
